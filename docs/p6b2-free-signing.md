# Code signing policy / 公司内部发行

更新：2026-10-04。用户明确客户端仅供自己公司使用，由管理员准备后交付；取消 SignPath 申请路线。此前免费申请材料保留为历史准备记录，不提交申请。第三方公众签名资格、公众 Windows 已发布记录和商业证书不作为本次内部发行前置条件。

## 简化后的方向

由管理员维护一个固定的内部代码签名身份，首次在受控公司电脑上明确配置其信任；随后同一身份签署安装器及程序目录清单，现有安装器验证发布者和文件完整性。以后更新复用这套身份，不为每次构建换临时证书。

管理员负责发布和首次部署；员工使用网页下载、解压和图形安装器。服务安装仍需正常 Windows 管理员授权。内部信任不保证任意电脑无 SmartScreen 提示，也不能静默越过系统安全限制。

## 保留的边界

- 签名私钥仅由管理员控制的发布环境持有，不进入服务器、客户端包或设备配置。
- 内部代码签名证书的信任由受控管理员部署；不能由尚未获信任的程序自证可信，首次 bootstrap 必须有独立可信分发和指纹核对。
- 继续验证有效签名、确切发布者、payload catalog、每文件摘要和时间戳。内部发行不等于未签名回退；当前生产导出门禁不在本次文档变更中删除。
- Windows 代码签名信任与 VPS TLS 信任相互独立。VPS 证书仍是 profile-local pin，不导入机器 TLS 根信任。
- 续期、撤销、私钥恢复和受认证的证书轮换集中放进发布流程处理，不临时要求员工管理证书。
- 固定身份创建/复用及首次受控信任工具已实现，见 [内部发行流程](p6b2-internal-release.md)。真实公司身份、时间戳签名导出及部署仍待验收；既有短期 lab 包不能自动变成正式包。

## 数据与授权

启用的设备向配置绑定的 VPS 上传时间、网络测试状态与延迟、公网出口 IP 和设备标签；控制密钥不作为样本上传。检测会访问配置的网络目标和 IPLark。用户可暂停、移除、撤销、清理和卸载，VPS 历史记录遵循既有 retention 规则。签名包不包含 Device Bundle、密钥、客户 YAML 或队列。

MIT 许可仍是用户已确认的独立授权决定，第三方组件保留原许可证。发布前仍核对随包通知和隐私说明。

当前管理员工具与测试只操作隔离测试证书，不更改现有 Windows 服务/Clash/TUN/VPS。用户已授权剩余条件解决且最终复核通过后合并；PR #70 在条件完成前仍为 Draft，生产部署和 P6C/P6D 未获授权。

依据：[微软：企业受控信任可用于内部自签发行](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)。Issue #67 §22 中用户最新的内部发行修订优先于历史公众签名准备说明。
