# Windows 双 VPS 主备配置工具（HA-UI 0.2.0）— 操作说明

适用：Windows 10/11 x64 本机；两台已安装本仓库 sing-box + `miaomiao` 管理入口的
VPS（A/B）。

0.2.0 的日常流程是：

```text
连接 A/B  →  新建或选择同名客户端  →  选择 A-first / B-first  →  生成 YAML
```

安全边界：

- **生成 YAML**：完全在本地进行；不建公网服务、不监听端口、不自动导入 Clash/Verge、
  不开启 TUN、不修改系统代理、不激活 Monitor/E3 管理面。
- **新建客户端**：是远程写操作，只通过已审查的 `install.sh` 菜单 10 → 2 创建；会修改
  两台 VPS 的 sing-box 客户端配置，并可能执行 reload。两端写入不是原子事务；A 成功、
  B 失败时保留 A，不自动删除。
- 更完整的安全模型见 `docs/windows-ha-ui-security.md` 与
  `docs/windows-ha-ui-data-path.md`。

## 1. 前置条件

- 两台 VPS 均可用 **root** SSH 登录（本版本仅支持 root；非 root 会明确报错，不尝试 sudo）。
- 服务器已安装本仓库的 sing-box + `miaomiao`；`/root/sbox/sbconfig_server.json` 与
  `/root/sbox/config` 存在，`jq`、`openssl`、`sha256sum`、`date` 等依赖可用。
- `/var/lib/sbox-cm/management.active` **不存在**（E3/Monitor 管理面未激活）。若存在，
  软件拒绝创建与生成，避免跨管理事务边界操作。
- 本机输出目录在 `%LOCALAPPDATA%\HASingbox`（受 NTFS ACL 保护，含凭据材料）。不要
  同步到网盘/OneDrive，也不要提交到 Git。

## 2. 首次配置 A/B

1. 启动 `ha-ui.exe`。默认进入「客户端」页；首次使用先切到「服务器」。
2. 分别填写 A、B 的名称/别名、IP 或主机名、SSH 端口、用户名（root）、SSH 密码。
3. 点「获取并确认指纹」：工具只读取 SSH 主机公钥（不发送密码），显示算法与
   `SHA256:...` 指纹。请与云控制台或服务器
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 的结果**人工核对**，勾选
   「我已核对」再保存。指纹不符或变更时，连接会在发送密码前被拒绝。
4. 「记住密码」只在勾选时保存到 **Windows 凭据管理器**；失败会明确报错，不会退回
   明文文件。
5. 点「测试连接」验证 root、Linux、配置文件、`miaomiao` 是否存在（只读）。

回到「客户端」页，点「刷新客户端」读取两端清单。顶部会显示 A/B 连接状态、客户端数量
和证书状态。

## 3. 新建客户端（0.2.0）

1. 点击主按钮 **「＋ 新建客户端」**。
2. 输入名称。允许规则：字母/数字开头，仅字母、数字、点、下划线、横线，长度 1–32；
   `legacy` 是保留名称，不能新建。
3. 阅读写入提示并勾选「我已了解并确认修改两台 VPS 的客户端配置」，点「创建」。
   - 目标固定为 A + B 两端同名。
   - 两端各自生成独立的 Reality UUID 与 HY2 密码，不跨服务器同步。
4. 软件先检查两端在线、名称不存在、协议结构可添加、证书身份合格，然后：
   - 按 A → B 顺序调用既有 canonical add；
   - 每端由 `with_client_lock` 串行化，执行 `sing-box check`、备份、原子替换、
     reload/health 与失败回滚；
   - 创建后重新读取两端 live 清单，只有名称与 Reality/HY2 都出现时才报告成功。
5. 成功后会显示「客户端已创建」，自动刷新并选中该客户端，切到「生成 YAML」页。

### 部分成功与补齐

- **A 失败**：不会尝试 B；界面显示两端实际状态。
- **A 成功、B 失败/待确认**：显示「创建未全部完成」，保留 A，**不会自动删除 A**，
  也不会把部分成功显示为完成。请先检查 B 的实际状态，再决定是否重试。
- **名称仅一端已存在**：默认停止，不写任何一端。若确认要补齐，软件会再次询问
  「是否只在缺失端创建同名客户端？」；确认后只创建缺失端，已有端凭据不会被修改、
  覆盖或删除。
- **两端都已存在**：直接停止，不覆盖。
- **超时/连接中断**：显示「待确认」，先刷新读取实际状态，不要盲目重发创建。

## 4. 读取客户端与生成 YAML

1. 在「客户端」页刷新后，表格只显示：名称、A 端状态、B 端状态、生成状态、
   优先节点。
   - A/B 端状态：`正常` / `异常` / `缺失`。
   - 生成状态：`可生成` / `待生成` / `缺少 A 端` / `缺少 B 端` / `配置异常`。
   - `待生成` 表示协议完整但规范导出缺失/过期，仍可选择；生成时会要求勾选同意运行
     `miaomiao` 菜单 3。
   - 被阻止的行没有复选框；点「查看原因」可看固定结构诊断，不显示原始远端输出。
2. 勾选客户端并选择 A-first 或 B-first（默认 A-first）；点底部「生成 YAML」进入生成页。
3. 生成页只显示「已选 N 项」、主按钮「生成 YAML」和结果区域。探测策略、进度日志、
   重试/删除失败目录在「高级选项」中。
4. 默认策略 **5s / 5000ms**；旧 5s/2000ms、3s/1000ms、10s/5000ms 仍可选。
   HA-03 的 60s/5000ms 版本保留在本次运行目录的 `ha03/<name>-hac.yaml` 作为对照。
5. 若所选客户端在至少一端缺少最新导出，页面才显示同意项；勾选后工具执行现有
   `miaomiao` 菜单 10 → 3 生成派生文件（不修改 sing-box 配置）。导出已新鲜时不会
   执行脚本。
6. 生成成功后显示「已生成 N 个文件」与「打开文件夹」；每个文件可在结果表中打开
   所在目录。不会自动导入任何客户端。

## 5. 失败、重试与回滚

- **生成重试**：点「高级选项」中的「重试」会用新的 run id 重新生成；失败运行目录
  可单独删除。历史成功目录不会被覆盖。
- **创建失败**：按界面显示的安全错误码处理；不要直接编辑服务器 JSON，也不要重复
  发送创建请求来“碰运气”。
- **创建结果待确认（`E_CREATE_UNCERTAIN`）**：界面会显式写“可能已写入服务器”，并
  自动刷新两端真实状态。刷新完成前不要重建同名客户端；刷新失败会显示
  `STALE / UNKNOWN`，此时本地显示可能已过期，不能据此判断服务器没有被修改。
- **远端事务仍在执行**：如果软件提示“远端创建事务尚未结束”，说明它只是停止等待，
  **没有**终止远端的提交。请稍后刷新；只有读到事务的终局（或确认没有事务记录）后，
  界面才会解除同名重建的禁令。普通刷新本身不会解除。
- **已回滚 ≠ 可能已写入**：只有服务端明确打印“已回滚并重新加载上一份配置”，且软件
  核对到配置字节回到写入前、名称不存在时，才显示“已回滚，配置已恢复（未提交）”。
  “回滚恢复失败”或“服务未能确认恢复”一律按待确认处理，需要人工检查。
- **部分创建**：不要删除已成功的一端来“重来”，因为删除可能触发凭据吊销；先确认
  缺失端状态，再决定补齐或人工处理。
- **服务端回滚**：canonical add 在 `sing-box check` 或 reload/health 失败时按既有
  `commit_server_config` 逻辑回滚并保留备份；软件只报告结果，不自行再回滚。
- **本地清理**：删除 `%LOCALAPPDATA%\HASingbox` 与 Windows 凭据管理器中的
  `ha-ui-ssh` 条目即可移除本地数据；不会自动删除服务器客户端。

## 6. 常见错误码

| 码 | 含义 | 处理 |
| --- | --- | --- |
| `E_HOSTKEY_MISSING` / `E_HOSTKEY_MISMATCH` | 未确认指纹 / 指纹变化 | 先独立核对；变化时停止并排查 |
| `E_SSH_AUTH` | 用户名或密码错误 | 检查凭据；必要时删除并重新保存 |
| `E_SSH_CONNECT` / `E_SSH_TIMEOUT` | 网络/端口/超时 | 检查连通性；超时后先刷新实际状态 |
| `E_REMOTE_PREFLIGHT` | 前置检查失败（detail 指明项） | 按 detail 修复；`management-active` 需人工处理 |
| `E_CLIENT_EXISTS` | 名称已存在 | 不覆盖；确认是否要改用补齐流程 |
| `E_CLIENT_PARTIAL_EXISTS` | 仅一端已存在 | 默认停止；确认后只补齐缺失端 |
| `E_CLIENT_INCOMPLETE` | 已存在端的协议不完整 | 先按服务端流程修复一致性，不覆盖凭据 |
| `E_REMOTE_CREATE` | 创建被拒绝或已回滚 | 按 detail 处理：`lock`/`consistency`/`create` 等为预写拒绝；`rolled-back` 为已证明回滚；`rollback-failed`/`rollback-unconfirmed`/`refusal-after-write` 需人工核实 |
| `E_CREATE_UNCERTAIN` / `E_REMOTE_VERIFY` | 写入结果待确认 / 创建后无法确认 | 先刷新读取 live 状态；`STALE` 时恢复连接再读，不要盲目重发 |
| `E_REMOTE_PIN` / `E_PIN_EXPIRED` / `E_PIN_REUSED` | HY2 证书问题 | 续签/换证书；A/B 不可同 PIN |
| `E_REMOTE_MENU` | 现有菜单执行失败或不可识别 | 查看固定 detail；不要手工改菜单输入 |
| `E_INSTALLER_UNTRUSTED` | installer/lib 不在已审查范围 | 不重试；升级需新版本重新审查 pin |
| `E_CHAIN_STAGE` / `E_CHAIN_CHECK` | HA-02/03/04 阶段或 `--check` 失败 | 按 detail 修复后重试 |
| `E_FRIENDLY_EXPORT` | 交付发布失败 | 检查目标目录/重试为新 run |
| `E_ACL` | 本地私有目录 ACL 校验失败 | 停止；不要移到共享/同步目录 |

## 7. 不要做的事

- 不要把 `%LOCALAPPDATA%\HASingbox`、YAML、manifest、截图或日志发到聊天/Issue/PR/CI。
- 不要在 Monitor/E3 管理面激活期间创建或生成。
- 不要手工编辑服务器 `sbconfig_server.json`，不要直接调用 `sbox-cm` worker 绕过
  Session/激活门禁来创建客户端。
- 不要让多个进程同时操作同一账号/同一输出目录；服务端锁只保护单次 canonical
  transaction，不能把两端变成原子事务。
- 不要在未确认实际状态时重发创建请求；也不要把“已生成 YAML”理解为已导入或已切换
  客户端。
