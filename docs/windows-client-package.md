# Windows 客户端包

在 Monitor 的客户端管理中，为每台电脑单独登记设备。设备登记确认后，
点击“下载 Windows 客户端包”。同一个客户端账号的不同电脑仍各有独立上传身份。

1. 完整解压 ZIP，保留同目录文件。
2. 将 `<client>-mihomo.yaml` 导入 Clash 并启用；本机 API 地址按配置要求设置。
3. 运行 `P6Setup.exe`。程序显示名称是“客户端管理”。核对自动识别的客户端和设备，
   再点击“安装 / 更新”；仅识别配置不会安装或启动服务。
4. 安装后可在程序中查看采样、上传确认、队列和后台服务状态。
   关闭窗口后后台服务继续运行。暂停、恢复、移除、清除和卸载都由明确操作触发。

同目录有多个配置时需要手动选择。旧版单独下载的设备配置也兼容；旧配置缺少名称时
明确显示为旧设备，不用内部标识冒充设备名。内部标识在“技术详情”中查看。
位置和网络路径是登记时填写的标签，不代表程序推断的地理位置或故障归因。

整个下载包包含代理凭据和设备上传密钥，只供所选设备使用，请私密保管。
`server.pem` 仅由客户端按固定证书验证连接，不导入系统证书库。
受控测试签名包会明确标注为测试用途，不能用于正式发布。

## 实现与发布边界

POST `/api/v1/clients/windows-bundle` 只接受 `{name,device}`，沿用登录、来源、
CSRF 和最新管理状态约束。软件发布文件先通过完整性/兼容性检查，再调用同一敏感
配置导出 RPC，保留当前 credential generation、live enrollment proof 和审计。
两种导出共用两个下载槽；不新增身份或旋转密钥，不落盘缓存组合包。

原签名软件文件按字节保留。软件以最多 64 KiB 块流式输出，设备配置最多 5 MiB，
组合 ZIP 最多 70 MiB / 71 entries / 64 KiB central directory。
下载总时限 60 秒，单次 socket write 时限 10 秒；响应禁止缓存。
原独立软件和配置端点保留兼容，公网 ingress 路由不变。

Bundle v2 只增加显示元数据，Agent profile v1、profile_id、HMAC 和存储协议不变。
Windows 将显示元数据保存在受保护的 display.json，与 probe_id/server_id 精确绑定；
冲突配置拒绝覆盖。旧 Bundle v1 仍可读取。

一键导出在读取设备凭据前，检查原签名目录内 release.json 的 gui-v2 能力标记。
旧 gui-v1 程序仍可单独下载，但不能组合成新版客户端包。

本批必须重新构建并签名 Windows 程序后才能在测试 VPS 发布和进行真实验收。
此前发布的签名 EXE 不会因服务器代码更新而变化。
生产签名、真实验收与独立复审仍是整个 P6B2 收口条件；PR #70 保持 Draft。
